## 구현된 ROS 경로

AssignmentSet은 ROS 객체와 분리된 순수 상태다. 서버와 로봇별 lease, 실행 UUID와 배정
버전을 확인하며 반복 목록 조회로 로봇을 다시 만들지 않는다. 종료 확인을 보낸 실행은 늦은
snapshot에 남아 있어도 되살리지 않는다. 종료한 실행의 기록은 10000개로 제한하며 상한에
도달하면 새 서버 UUID로 재시작하도록 로컬 권한을 만료시킨다.

DistributedManager는 HTTP와 ROS executor를 분리한다. ASSIGNED 로봇만 생성하며
RELEASING에서는 실제 idle 또는 arrived와 미처리 수신함 부재를 확인한 뒤 자원을 해제한다.
이동 중 로봇은 정상 이전을 기다린다. 삭제 요청과 lease 만료는 기존 실행을 중단한다.
실행 서버마다 별도 Kafka group을 사용하고 다른 서버 대상의 정상 명령은 건너뛴다.
자기 서버 대상의 오래된 실행 UUID와 배정 버전은 DLQ 계약으로 처리한다.

구독 콜백은 관측을 받은 실행 UUID를 유지한다. HTTP 스레드가 새 배정을 반영하는 시점과
ROS 콜백 처리 시점이 겹쳐도 이전 pose 또는 status에 새 UUID를 붙이지 않는다.
영속 경로는 기존 저널과 Ack 회수를 유지하며 기본 설정은 계속 비활성화다.

## 검증과 남은 작업

ROS2 컨테이너에서 실제 노드를 생성해 다른 로봇의 추가와 해제 중 이동이 지속되는지,
이동 중 정상 해제를 기다리는지와 늦은 snapshot의 재생성 차단을 검증했다. 순수 테스트로
배정 반복, 만료, 다른 서버 명령 분리와 group 유지 및 잘못된 토큰을 검증한다.

이 변경은 ROS 초안 단계다. 이 코드만으로 분산 실행을 활성화하지 않는다. 로봇별 API
검증과 명령 접수, 보고 및 온라인 및 조회 경로 연결, Compose 설정과 실제 1 → 3 → 1
및 장애 검증은 남아 있다. 명령 영속 경로와 분산 모드 기본값은 계속 비활성화다.
README는 변경하지 않는다.
