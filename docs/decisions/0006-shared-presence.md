# ADR 0006: API 간 온라인 판정 공유

- 상태: 구현과 검증 완료
- 관련 이슈: https://github.com/sor999/rokin/issues/37

## 결정

PostgreSQL의 `robot_presence`를 온라인 관측의 공통 저장소로 사용한다. 이미 실행 의도,
설정 버전, 현재 runtime의 epoch를 보유한 DB에서 관측과 소유권을 함께 읽어 API마다
다른 캐시 상태로 명령을 허용하지 않게 한다. Redis는 전달 계층으로 유지한다. 별도 Redis
presence와 DB 사이의 무효화 순서 및 장애 시 모순을 만들지 않는 선택이다.
이 단계에서는 이벤트당 한 번 쓰는 비용을 수용하며 조회와 쓰기 최적화는 3단계에서 측정한다.

## 소유권과 만료

- DB의 simulation 등록, 삭제 의도, 설정 버전, 최신 epoch가 실행 권한의 기준이다.
- presence는 Fleet, robot, runtime별 최신 관측 시각만 저장한다. runtime 없는 정적 로봇은
  빈 문자열 키를 사용하며 등록된 관리 로봇과 혼합하지 않는다.
- Kafka 입력을 소비한 API만 presence를 갱신한다. Redis 수신 API와 SSE 전송은 갱신하지 않는다.
- 로봇 timestamp의 최대값을 보존한다. 기본 30초보다 오래된 입력은 presence와 실시간
  전달에서 제외한다. Worker의 이력 적재에는 영향을 주지 않는다. 과거 메시지를 재수신해도
  수신 시각으로 온라인 유효기간을 연장하지 않는다.
- 관측 만료와 실행 heartbeat 모두 DB 시간을 사용해 API 서버 간 시계 차이를 배제한다. 로봇 시계는 DB와 동기화되어야 한다.
  5초를 초과한 미래 timestamp는 제외하고 허용 범위의 미래 시각은 DB 현재 시각으로 제한한다.
- 온라인 조회는 하나의 SQL 스냅샷에서 관측 만료, 현재 Fleet과 runtime, 삭제 의도,
  RUNNING 보고 및 10초 heartbeat를 검사한다. 이전 runtime의 지연 쓰기는 현재 실행의
  온라인 여부에 영향을 주지 않는다. 만료한 이전 runtime 관측은 1일 후 정기 정리한다.
- ID 재사용 금지 및 이력 보존 계약은 유지한다. presence 정리는 텔레메트리 이력을 삭제하지 않는다.

## 명령과 실패

이동과 정지는 동일한 공유 온라인 조건으로 검사한다. 관리 로봇의 명령에는 기존 설정 버전과
runtime을 계속 포함한다. 판정 직후 소유권이 바뀌는 경쟁은 기존 ROS fencing으로 실행을 차단한다.
정적 로봇 명령도 공유 온라인 관측이 필요하다.

DB 조회 실패 시 로컬 상태로 대체하지 않는다. REST는 실패를 반환하고 명령은 접수하지 않는다.
온라인 조회가 실패하면 HTTP 503을 사용하며 STOMP는 기존 명령 오류 응답을 사용한다.
주기적 오프라인 검사에서 DB 장애를 감지하면 SSE를 닫아 화면의 재연결과 REST 재조회를 유도한다.
화면은 연결 오류를 표시하고 온라인 표시를 해제한다. HTTP 503으로 브라우저가 연결을 완전히 닫아도 2초 간격으로 새 SSE 연결을 만들며, 화면을 떠나면 대기 재시도와 조회를 정리한다. 재연결 시 REST로 복구하되 조회 중 수신한 SSE를 오래된 응답이 덮어쓰지 않게 한다. 현재 데이터를 확인할 수 없는 동안 온라인임을 보장하지 않는다. Kafka의 DB 오류는 잘못된
payload로 삼키지 않고 소비 오류로 전파한다. Redis 장애 시에도 기존 준비 상태 차단을 유지한다.

API 재시작과 Redis 재연결은 공유 관측을 지우지 않는다. 만료 전이면 첫 신규 이벤트를 받기
전에도 다른 API와 같은 판정이다. DB 복구 후 다음 조회부터 동일 기준으로 수렴한다.
ROS 재시작은 새 runtime의 준비 보고와 새 관측이 모두 있어야 온라인으로 판정한다.

## 구현 전 시나리오

| 시나리오 | 자동 검증 | 환경 검증 |
| --- | --- | --- |
| 다른 API와 재시작 | 독립 서비스의 공통 DB 판정 일치 | API 2대 REST와 양쪽 명령 |
| 지연과 중복 | 과거 timestamp가 만료를 연장하지 않음 | Kafka 이전 관측 주입 |
| runtime 교체와 삭제 | 이전 관측 및 지연 쓰기로 온라인 복구 불가 | ROS 재시작 후 수렴 |
| 저장소 단절 | 온라인 조회 503, Kafka 오류 전파 | 격리 DB 중단 후 복구 |

REST, SSE, Command/Ack의 공개 필드와 Worker 적재 스키마는 변경하지 않는다.
