# ADR 0009: Worker의 제한된 대기열과 파티션 소유권

- 상태: 구현 및 검증 중
- 관련: [확장성 계획](../features/distributed-scalability-plan.md), [Ack 저장](0002-ack-persistence.md)

## 결정

하나의 프로세스에서 텔레메트리와 Ack Consumer, 예약 예산, DB 풀을 분리한다.
구독 토픽은 겹치지 않으며 기존 group과 커밋 위치를 유지한다. Worker 3대의 DB 연결
예산은 기본값으로 15개다. DB 전체 장애 시 두 경로 모두 대기한다.

한 파티션은 한 배치만 실행한다. 실패한 배치는 고정하고 취소 가능한 작업 제한 시간과
1초부터 최대 5초의 백오프로 재시도한다. 파티션 사이에는 순환 스케줄링을 적용한다.
위치 이력을 합치거나 버리지 않는다. malformed payload는 DLQ 전달 확인 이후 완료한다.
크기 초과와 DLQ envelope 초과는 파티션을 중지하고 위치와 원인을 로그로 알린다.

모든 대기 및 실행 메시지는 원본 크기 8배에 8KiB를 더해 예약한다. 전체와 파티션의
건수 및 예약 바이트를 모두 제한한다. 최대 메시지 수용 공간이 없으면 Pause하고,
50% 이하이며 다시 수용 가능할 때 Resume한다. 이는 정확한 RSS 상한이 아니며
librdkafka 버퍼와 전체 프로세스 메모리는 따로 측정한다.

Consumer 소유 루프만 커밋한다. 실제 수신 순서의 완료 접두부를 추적하므로 Kafka
오프셋의 숫자 간격은 무관하다. 실패한 커밋은 완료 위치를 보존해 다시 시도한다.
할당 회수 즉시 세대를 무효화하고 작업을 취소한다. 이전 작업은 실제 종료까지
동시 실행 슬롯과 예약량을 점유하지만 새 세대의 커밋 위치를 바꾸지 못한다.

새 group은 보존 중인 가장 오래된 위치에서 시작한다. 기존 커밋이 보존 범위를
벗어나면 자동 건너뛰기를 금지하고 Worker를 오류 종료한다. 운영자가 원인을 확인한다.
정상 종료는 소비 중지, 최대 20초의 정리, 안전한 커밋, 클라이언트 종료 순서다.
미완료 메시지는 커밋하지 않고 재할당 후 재처리하며 DB의 event_id와 Ack 전이 계약을 유지한다.

## 검증 시나리오

| 시나리오 | 준비 | 자동 검증 | 수동 확인 |
| --- | --- | --- | --- |
| DB 중단과 복구 | 격리 Kafka와 PostgreSQL | 상한, 재시도, 전량 적재 | RSS와 lag 수렴 |
| 재할당 | 3개 파티션 | 세대 무효화 및 이전 완료 차단 | Worker 1에서 3, 다시 1대로 변경 |
| Ack 격리 | pose 적재 지연 | 별도 Consumer와 풀 | Ack 저장 p95 2초 이내 |
| 강제 종료 | 미커밋 배치 | 중복 재전송과 DB 멱등성 | 데이터 누락 및 상태 역행 없음 |

## 도입

기존 Worker를 정상 종료한 뒤 같은 group으로 교체한다. 오프셋과 볼륨을 초기화하지
않는다. 스키마 및 REST와 메시지 계약은 바꾸지 않는다. 명령 영속 경로의 기본
비활성화도 유지한다. 장애 및 부하 수치는 격리 환경의 실행 결과로 별도 기록한다.
