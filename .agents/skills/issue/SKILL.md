# 이슈 작성

- 저장소 루트의 `AGENTS.md`와 [Git 컨벤션](../git-conventions/SKILL.md)을 확인한다.
- 기능은 [기능 템플릿](../../../.github/ISSUE_TEMPLATE/feature_request.md), 버그는 [버그 템플릿](../../../.github/ISSUE_TEMPLATE/bug_report.md)의 구조를 유지한다.
- 제목은 한국어로 작성하며 타입 뒤 scope와 이슈 번호를 넣지 않는다.
- 기능 제목은 `feat: 로봇 상태 필터 추가`처럼 작성한다. 버그 제목은 기존 템플릿의 `bug: ` 접두사를 따른다.
- 기능의 `✨ 구현할 기능`에는 기능과 필요한 이유를, 버그의 `🐛 버그 내용`에는 재현 조건과 기대/실제 동작을 작성한다.
- `📝 TODO`에는 요청 범위의 구체적인 작업만 체크박스로 작성한다.
- 관련 이슈를 확인할 수 있으면 중복 여부를 확인하고 기존 이슈를 우선 활용한다.
- 초안 요청은 본문 작성까지 수행한다. 게시 요청은 연결된 GitHub 도구 또는 `gh`로 생성하고 URL을 보고한다.

# 어투

- 간결한 개조식 및 명사형 종결 사용
- 목록은 하이픈 또는 체크박스로 통일하고 중단점(·) 혼용 금지
